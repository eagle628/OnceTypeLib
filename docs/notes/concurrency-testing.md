# 並列テストについて

今回はLock-Freeライブラリということもあり、テストとして、Concurrencyについてのテストを実装してみた。知見としては保持していたつもりだったので、AIが作るコードベースをレビューする方針で作ってみた。割合思った通りのテストが出てきていたので、それについてはそこまで気にする必要はなさそう。

ただ、大きな知見として、今までローカルテストしかしていなかったがCI/CDを使った運用だと非常に小さいリソースしか利用できない環境にある。特に.NET Frameworkのテストを実施した時に、Timeoutで落ちた。念のためでしかなかったTimeoutが有効になった瞬間だったので今後もConcurrency系（というかDeadLockのありそうな）テストにはTimeoutをつけるべき。

Timeoutで落ちた要因としては、ThreadPoolを使ってスレッドを利用して同時にデータを書き込む動作を模擬しようとしたときに、`Task.Run`を使っていたのでスレッドプールを使い果たしてDeadLockしたのだろうと思われる。ほぼ使ったことのなかった`TaskCreationOptions.LongRunning`を使ってみたが、これでもうまくいかず、実行待ちで無限Loopを使っていたところに`Spinner`を使って、むりやりコンテキストを切り替えさせるようにするとうまくいくようになった。適切な回避策だったのかどうかはかなり不透明ではあるが、ローカルとAction上でのテストは通過したので多分いいのだろう。
